# User Rule: Automated Git Push and CI Verification Workflow
- **Always Push and Verify**: After completing a task or set of changes, you must always commit and push the changes to GitHub.
- **Verification Wait**: After pushing, use the `schedule` tool to set a 4-minute timer (`DurationSeconds=240`, `TimerCondition="never"`). Wait for the timer to fire without calling other tools to end your turn.
- **Check Status**: Once the timer fires, check the GitHub Actions build status (e.g. using `gh run list` with `git` in PATH).
- **Success Criteria**: If the action is still running after 4 minutes, assume it will succeed and stop your work (end your turn without further action).
- **Failure Recovery**: If the build has failed, pull the latest changes (`git pull --rebase origin main`), read the `error_log.txt` generated by CI, fix the compilation/build errors, commit and push again, and repeat the verification wait process. Do this every time.
- **Report Push Details**: After pushing, always state the "push number" (Commit Hash and GitHub Actions Run ID) on the screen for the user to see.

  ```bat

  "C:\Users\Rasel Mahmud\AppData\Local\GitHubDesktop\app-3.6.3\resources\app\git\cmd\git.exe" add .
  "C:\Users\Rasel Mahmud\AppData\Local\GitHubDesktop\app-3.6.3\resources\app\git\cmd\git.exe" commit -m "Your message here"
  "C:\Users\Rasel Mahmud\AppData\Local\GitHubDesktop\app-3.6.3\resources\app\git\cmd\git.exe" pull --rebase origin main
  "C:\Users\Rasel Mahmud\AppData\Local\GitHubDesktop\app-3.6.3\resources\app\git\cmd\git.exe" push origin main
  ```

  Run this with: `cmd.exe /c "scratch\push_fix.bat"`
